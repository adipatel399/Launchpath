# Demo

Open <https://launchpath-lpry.onrender.com>. The checked [Figma example](https://launchpath-lpry.onrender.com/guide/research-f0afbb4b-c19f-4d3d-a97b-d1438c26ac43) shows a live investigation followed by source checking.

## Start with an existing app

1. Open the app library and search for Gmail.
2. Compare inbox reading with sending only. The scope classification, assessment step and blocker information change.
3. Open a setup step and its evidence receipt.
4. Open the preparation packet and export it.

## Show practical setup

1. Open Slack and choose Let LaunchPath help.
2. Select the custom route, enter an app name and an HTTPS callback address.
3. Prepare the files and inspect the manifest. It is a draft, not an installed Slack app.
4. Open GitHub and choose the managed route to demonstrate a real connection when a test project key is configured.
5. Inspect the requested permissions, personally complete sign in and consent, then check the actual connection and run the profile read test.

## Try an unfamiliar app

1. Enter a provider that is not in the library.
2. Add a specific use case, including what the agent needs to read or change.
3. Watch the actual source retrieval and review activity.
4. Open the saved guide and inspect its permissions, release questions and sources.
5. Share the guide URL. Private website inputs and setup records are kept separate.

If a service times out, show the failure and remaining activity. Do not describe that result as evidence that the provider lacks OAuth.
